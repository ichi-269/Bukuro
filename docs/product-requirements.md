# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**Bukuro** - 読書ブログ＆本棚サービス

### プロダクトコンセプト
- **個人記録の快適さを最優先**: 非公開で使っても十分な価値があり、ISBNを入力するだけで書誌情報を自動取得できる
- **ブログとしての表現力**: 感想・レビューをブログ記事のように書いて残せる記事エディタを持つ
- **SNS機能は補助的**: フォロー・グッド等は「あると嬉しい」程度の位置づけ。個人記録を軸に設計する

### プロダクトビジョン
読んだ本の感想を丁寧に残したいと思いながらも、ExcelやNotionでは続かなかった読書家のための記録サービス。ISBNを入力するだけで書誌情報が自動補完され、ブログ記事のように感想を書いて蓄積できる。記録が増えるほど自分だけの読書史が形成される。公開すれば他のユーザーと読書体験を共有できるが、あくまで「自分のための記録」が設計の軸である。

### 目的
- 読書記録の継続障壁を下げる（ISBN入力→書誌自動補完で入力コストを最小化）
- ブログ形式の記事で感想を長期アーカイブできる環境を提供する
- 読書履歴の可視化により読書習慣の維持・改善を支援する
- 将来の月額サブスクリプション収益モデルの基盤を構築する

## ターゲットユーザー

### プライマリーペルソナ: 山田あかり（32歳、会社員）
- 月4〜8冊ペースで読書する読書好き
- 感想をSNSに流すだけでは物足りなく、きちんとアーカイブしておきたい
- 過去にNotionや読書メーターを試したが続かなかった
- スマートフォンとPCの両方を使う
- **現在の課題**: 読んだ本の感想をどこに書くか迷う。書誌情報を手入力するのが面倒で続かない
- **期待する解決策**: ISBNを入力するだけで本が登録でき、感想をブログのように書けるシンプルなサービス
- **1日の典型的なワークフロー**: 読書後にPCやスマートフォンを開き、ISBNで本を登録→感想を記事として記録→週1で読書グラフを確認

### セカンダリーペルソナ: 佐藤けんじ（28歳、エンジニア）
- 月10冊以上読む多読家
- 読書メーター等の既存サービスに不満があり、ブログに近い形式で記録したい
- 自分の記録を見返すことが習慣化している
- 他ユーザーの感想も参考にしたい（SNSとして活用する意図あり）

## 成功指標(KPI)

### 測定基準

- **起算日**: Phase 1完了・本番デプロイ日
- **測定タイミング**: 起算日から+90日時点で測定
- **MAUの定義**: 当月中に1回以上ログインしたユーザー数

### プライマリーKPI
- 登録ユーザー数: 100人（リリース後3ヶ月以内）
- 月次アクティブユーザー(MAU): 50人（リリース後3ヶ月以内）
- 1ユーザーあたり平均記録冊数: 5冊以上（3ヶ月後の平均）
- ユーザーあたり記事投稿数: 月3件以上（アクティブユーザーの平均）

### セカンダリーKPI
- 記事公開率: 全記事の30%以上が公開設定
- フォロー機能利用率: MAUの20%以上がフォロー機能を使用
- 継続率: 登録後1ヶ月後のリテンション率40%以上
- 月額課金転換率（将来）: 無料ユーザーの10%が課金（Phase 3以降）

## 機能要件

### コア機能（MVP / Phase 1）

#### ユーザー認証

**ユーザーストーリー**:
読書記録を残したいユーザーとして、自分のデータを安全に管理するために、メールアドレスとパスワードで登録・ログインしたい

**受け入れ条件**:
- [ ] メールアドレス＋パスワードで新規登録できる
- [ ] 登録済みユーザーがログイン・ログアウトできる
- [ ] パスワードはBCryptでハッシュ化して保存される
- [ ] 未ログイン状態でもホームページ・記事詳細・ユーザーページは閲覧できる
- [ ] ログインが必要な操作（本棚追加・記事作成等）には認証ガードがかかる

**優先度**: P0（必須）

---

#### ISBN検索・書誌情報自動取得

**ユーザーストーリー**:
本を記録したいユーザーとして、手入力の手間を省くために、ISBNを入力するだけで書誌情報（タイトル・著者・書影）を自動取得したい

**受け入れ条件**:
- [ ] ISBN-13またはISBN-10を入力フォームに入力できる
- [ ] OpenBD APIからタイトル・著者・出版社・書影URLを取得して画面に表示する
- [ ] APIから取得した書誌情報はユーザーが編集できない（OpenBD利用規約準拠）
- [ ] 該当書籍が見つからない場合はエラーメッセージを表示する
- [ ] 確認後「本棚に追加」ボタンで読書記録（reading_records）に登録できる
- [ ] すでに本棚に登録済みの本は重複登録できない

**優先度**: P0（必須）

---

#### 本棚管理（ステータス・星評価）

**ユーザーストーリー**:
読書記録をつけたいユーザーとして、本の状況を把握するために、積読・読中・読了のステータスと1〜5の星評価を管理したい

**受け入れ条件**:
- [ ] 本棚画面でステータス別タブ（積読・読中・読了）に分けて一覧表示できる
- [ ] ステータスを変更できる（積読→読中→読了 など）
- [ ] 読了ステータス時に1〜5の星評価を設定できる
- [ ] 読み始め日・読了日をカレンダーで入力できる
- [ ] 本棚から本を削除できる

**優先度**: P0（必須）

---

#### 読書記録ブログ記事の作成・編集・削除

**ユーザーストーリー**:
読んだ本の感想を残したいユーザーとして、後から読み返せるように、本に紐づけてブログ記事形式で感想・レビューを書きたい

**受け入れ条件**:
- [ ] 本棚に登録済みの本を選択して記事を作成できる
- [ ] 記事タイトルと本文テキスト（プレーンテキスト入力）を入力できる（Markdown対応はPhase 2以降）
- [ ] 公開・非公開を記事ごとに選択できる
- [ ] 作成した記事を編集できる
- [ ] 作成した記事を削除できる（削除は取り消し不可の確認ダイアログ付き）
- [ ] 公開記事は未ログインユーザーにも閲覧できる

**優先度**: P0（必須）

---

#### マイページ・記事一覧・読書グラフ

**ユーザーストーリー**:
自分の読書履歴を振り返りたいユーザーとして、記録の蓄積を実感するために、書いた記事の一覧と月別の読書冊数グラフを確認したい

**受け入れ条件**:
- [ ] マイページに自分のプロフィール（ユーザー名・自己紹介）が表示される
- [ ] 書いた記事が新着順に一覧表示される（公開・非公開ともに本人には表示）
- [ ] 月別読書冊数グラフ（Chart.js）が表示される
- [ ] プロフィール（ユーザー名・自己紹介）を編集できる

**優先度**: P0（必須）

---

### ソーシャル機能（Phase 2）

#### ユーザーページ

**ユーザーストーリー**:
他ユーザーの読書記録に興味があるユーザーとして、参考にするために、他ユーザーの公開記事と本棚を閲覧したい

**受け入れ条件**:
- [ ] ユーザーページに公開記事一覧が表示される
- [ ] ユーザーページに公開本棚（読了ステータスの本）が表示される
- [ ] 未ログインユーザーも閲覧できる

**優先度**: P1（重要）

---

#### フォロー機能

**ユーザーストーリー**:
興味あるユーザーの読書動向を追いたいユーザーとして、最新記事を把握するために、ユーザーをフォローしたい

**受け入れ条件**:
- [ ] ユーザーページからフォロー・アンフォローができる
- [ ] フォロワー数・フォロー中数がユーザーページに表示される
- [ ] 通知は不要（初期実装では通知機能なし）

**優先度**: P1（重要）

---

#### グッド（いいね）機能

**ユーザーストーリー**:
良い記事に反応したいユーザーとして、共感を示すために、記事にグッドを押したい

**受け入れ条件**:
- [ ] 記事詳細ページでログインユーザーがグッドを押せる
- [ ] グッド数が記事詳細・一覧に表示される
- [ ] 同一ユーザーが同じ記事に2回グッドできない
- [ ] グッドの取り消しができる

**優先度**: P1（重要）

---

#### ホーム画面（フィード）

**ユーザーストーリー**:
フォロー中のユーザーの動向を把握したいユーザーとして、最新の読書情報をキャッチするために、ホーム画面でフィードを確認したい

**受け入れ条件**:
- [ ] ログイン後ホーム画面にフォロー中ユーザーの最新公開記事が新着順で表示される
- [ ] フォロー中ユーザーがいない場合は全公開記事からグッド数順またはランダムでおすすめ記事を表示する
- [ ] 未ログイン時はサービス説明・ログイン・新規登録ボタンが表示される

**優先度**: P1（重要）

---

#### 本の詳細ページ

**ユーザーストーリー**:
特定の本について他の読者の感想を知りたいユーザーとして、多様な意見を参考にするために、その本に書かれた公開記事一覧を確認したい

**受け入れ条件**:
- [ ] 本の詳細ページに書誌情報（タイトル・著者・書影）が表示される
- [ ] その本に紐づいた公開記事が新着順に一覧表示される

**優先度**: P1（重要）

## 非機能要件

### パフォーマンス
- ページ初回表示: 2秒以内（モバイル回線含む）
- ISBN検索からOpenBD APIレスポンス表示: 3秒以内（外部API依存）
- 記事一覧ページ: 100件表示まで1秒以内

### ユーザビリティ
- 新規ユーザーが登録からISBN検索・本棚追加まで5分以内に完了できる
- スマートフォン（320px以上の画面幅）でも主要機能が使えるレスポンシブデザイン
- 日本語UIのみ（初期リリース）

### 信頼性
- OpenBD APIが利用不可の場合、エラーメッセージを表示してサービス全体は継続稼働する
- 記事・読書記録のデータ損失ゼロ（日次バックアップ・7日分保持）

### セキュリティ
- パスワードはBCryptでハッシュ化して保存
- Spring Securityを使用してセッション管理・CSRF対策を実施
- 他ユーザーの非公開記事・読書記録にはアクセスできない
- OpenBD利用規約に従い、書誌データの編集機能は提供しない
- 管理者が書誌データを削除要請に応じて削除できる管理機能を持つ

### スケーラビリティ
- 初期リリース: 100ユーザー・10,000記事を想定した設計
- Render / Railway へのデプロイを前提とした構成

- コメント機能（記事へのコメント）
- 記事への画像添付（書影以外）
- 通知機能（フォロー・グッドの通知）
- DM・メッセージ機能
- 多言語対応
- 読書時間タイマー
- モバイルアプリ（iOS / Android）

## 実装フェーズ

ユーザー認証・ISBN検索・本棚管理・読書記録ブログ・マイページ・読書グラフ

### Phase 2: ソーシャル機能
ユーザーページ・フォロー・グッド・ホームフィード・本の詳細ページ

### Phase 3: デプロイ・公開
Render / Railway へのデプロイ・独自ドメイン設定・月額課金検討
