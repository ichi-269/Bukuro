# 要求内容

## 概要

Bukuroのフロントエンドを、現在のSpring Boot + Thymeleafによるサーバーサイドレンダリング(MPA)構成から、Vue 3 + TypeScript + Viteによる本格的なSPA(Single Page Application)構成へ全面的に移行する。バックエンドは既存のController群を`@RestController`によるJSON APIへ書き換える。

## 背景

- 現状は全ページがThymeleafでサーバーサイドレンダリングされており、独自JavaScriptは存在しない(Bootstrapのバンドルスクリプトのみ)。
- ユーザーがフロントエンドフレームワークを用いた実装を試したいという意向があり、学習・技術検証を兼ねて本格的なSPA化に取り組む。
- 既存の認証方式(Spring Security セッションCookie)・DB構成・ビジネスロジック(Serviceレイヤー)は変更せず、プレゼンテーション層のみを置き換える。

## 決定事項(意思決定済み)

| 項目 | 決定内容 |
|------|---------|
| フロントエンドフレームワーク | Vue 3 + TypeScript + Vite |
| 移行方針 | 全面書き換え(ビッグバン)。段階的な新旧併存は行わない |
| 認証方式 | 既存のSpring SecurityセッションCookie認証を継続。SPAは`credentials: include`でfetch/axiosし、CSRFトークンはメタタグ等でSPA側に渡す |
| デプロイ構成 | Vueのビルド成果物をSpring Bootの`static/`配下に統合し、単一サービスとしてデプロイ(現行のRender/Railway単一Webサービス構成を維持) |

## 実装対象の機能(現行MPAの全画面をSPA化)

### 1. ユーザー認証
- 新規登録・ログイン・ログアウトをAPI経由で実行し、画面遷移なしで結果を反映する
- 未ログイン状態でもホーム・記事詳細・ユーザーページ等の公開ページはSPA側で閲覧可能にする

### 2. ISBN検索・書誌情報取得・本棚追加
- ISBN入力→OpenBD検索結果表示→本棚追加までをページ遷移なしで行う

### 3. 本棚管理
- ステータス別タブ(積読・読中・読了)表示、ステータス変更、星評価、読書日入力、削除をSPA上で行う

### 4. 読書記録ブログ記事(投稿)
- 記事の作成・編集・削除・詳細表示・公開/非公開設定をSPA上で行う

### 5. マイページ・プロフィール編集
- プロフィール表示・編集、記事一覧、月別読書グラフ(Chart.js)表示をSPA上で行う

### 6. ユーザーページ・フォロー・グッド
- 他ユーザーページの公開記事・本棚表示、フォロー/アンフォロー、グッド追加/取り消しをSPA上で行う

### 7. ホームフィード
- ログイン時のフォロー中フィード、未ログイン時のサービス説明表示をSPA上で行う

### 8. バックエンドAPI化
- 既存の`@Controller`(Thymeleafビュー返却)を`@RestController`(JSON返却)へ全面的に書き換える
- 既存のDTO(`dto/`パッケージ)を必要に応じてAPIレスポンス用に見直す
- Thymeleafテンプレート・`thymeleaf-extras-springsecurity6`依存は撤去する

## 受け入れ条件

### 機能的パリティ
- [ ] 現行`docs/product-requirements.md`のPhase1・Phase2に定義された全受け入れ条件が、SPA版でも満たされる
- [ ] 既存のE2Eフロー(新規登録→ISBN検索→本棚追加→記事作成→公開)がSPA上で完了できる
- [ ] 非公開記事・他ユーザーリソースへのアクセス制御が従来通り機能する(セッション認証・所有権チェックはServiceレイヤーを流用)

### 技術要件
- [ ] Vue Router によるクライアントサイドルーティングが機能し、直接URLアクセス(リロード)でも正しい画面が表示される
- [ ] CSRF対策(トークン送信)がAPI呼び出し全てで機能する
- [ ] 既存のバリデーションルール(フォーム入力チェック等)がAPIレスポンスのエラーとしてSPA側に伝わり、UIに表示される
- [ ] `mvn verify`によるバックエンドテスト(Service/Repository)は既存のまま通過する

### 非機能要件
- [ ] ページ初回表示2秒以内(モバイル回線含む)を維持する
- [ ] レスポンシブデザイン(320px以上)を維持する

## 成功指標

- 既存のThymeleafベース機能が全てSPA版で再現され、`docs/product-requirements.md`のPhase1・Phase2受け入れ条件を満たす
- 技術検証として、Vue 3 + TypeScript + Viteによる実装パターンがプロジェクトに確立される

## スコープ外

以下はこのフェーズでは実装しません:

- 新機能の追加(Phase 3の月額課金・タグ検索等は引き続きスコープ外)
- JWT等トークンベース認証への変更(セッションCookie認証を継続するため)
- フロントエンド・バックエンドの別ホスティング化(単一サービスデプロイを維持)
- モバイルアプリ化
- SSR(サーバーサイドレンダリング)対応(CSR SPAとして実装)
- 段階的移行・新旧併存(ビッグバン移行のため)
